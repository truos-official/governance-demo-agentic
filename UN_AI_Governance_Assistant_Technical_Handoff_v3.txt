1. PROJECT OVERVIEW
================================================================================

A production-grade AI governance assistant built on 9 UN policy documents.
Demonstrates responsible AI principles: RAG retrieval, hallucination detection,
PII anonymization, semantic caching, adversarial query protection, and
fine-tuned LLM responses.

Tech stack:
  - Backend:   FastAPI (Python 3.11), deployed as Azure Container App
  - Frontend:  React, deployed as Azure Static Web App
  - LLM:       GPT-4o-mini (fine-tuned on UN governance corpus)
  - Retrieval: Hybrid BM25 + kNN over Elasticsearch (2,059 chunks, 9 docs)
  - Cache:     Azure Cache for Redis (semantic cosine similarity >= 0.95)
  - Security:  Azure Language Services (PII detection/redaction)
  - Observability: LangSmith (LLM tracing), Weights & Biases (eval tracking)

8. LOCAL DEVELOPMENT SETUP
================================================================================

Prerequisites:
  - Python 3.11
  - Node.js 20+
  - Docker Desktop
  - Azure CLI (az login as info@truos.io)

Step 1 — Clone and configure:
  git clone https://github.com/truos-official/governance-demo-agentic.git
  cd governance-demo-agentic
  cp .env.example .env
  # Fill in all values in .env (see Section 5 for where to get each secret)

Step 2 — Backend:
  python -m venv venv
  venv\Scripts\activate          # Windows
  pip install -r requirements.txt
  uvicorn src.api:app --reload --port 8000

Step 3 — Frontend:
  cd frontend
  npm ci
  npm start                      # Starts on http://localhost:3000
  # Uses REACT_APP_API_URL=http://localhost:8000 from frontend/.env

Step 4 — Docker Compose (alternative to steps 2+3):
  docker-compose up --build
  # Backend: http://localhost:8000
  # Frontend: http://localhost:3000

CORS in local dev: http://localhost:3000 is always in the default CORS_ORIGINS.

10. DATA LAYER
================================================================================

--- ELASTICSEARCH ---
Provider:  Elastic Cloud on Azure (elastic.co)
Index:     un_documents_index
Endpoint:  https://my-elasticsearch-project-f2452a.es.eastus2.azure.elastic.cloud:443
Chunks:    2,059 (chunk size 500 tokens, overlap 50)
Mapping:
  content    → text (BM25 keyword search)
  source     → keyword
  embedding  → dense_vector, dims=1536 (text-embedding-3-small)

Retrieval strategy (elastic_retriever.py):
  hybrid_search() = keyword_search(top_k*2) + vector_search(top_k*2)
  → deduplicate by _id → sort by _score → return top_k

To rebuild index from scratch:
  python src/elastic_indexer.py
  (requires ELASTIC_ENDPOINT, ELASTIC_API_KEY, OPENAI_API_KEY in .env)

--- REDIS ---
Instance:  governance-redis.redis.cache.windows.net:6380 (SSL)
Provider:  Azure Cache for Redis, Basic C0, Redis 6

Key schema:
  user:{user_id}:profile          → JSON string (user registration data)
  users:all                       → Set of all user_ids
  users:approved / pending / revoked → Sets by status
  metrics:total_queries           → Counter
  metrics:style:{style}           → Counter per query style
  metrics:source:{doc}            → Counter per source document
  metrics:latencies               → List (last 1000 latency values, float)
  metrics:cache_hits              → Counter
  metrics:hallucinations          → Counter
  metrics:pii_detected            → Counter
  metrics:pii_entity:{type}       → Counter per PII entity type
  security:injection / pii / rate_limit → Security event counters
  user:{id}:total_queries         → Counter
  user:{id}:hallucinations        → Counter
  user:{id}:style:{style}         → Counter
  user:{id}:latencies             → List
  user:{id}:last_active           → ISO timestamp string
  feedback:{query_id}             → JSON string (feedback record)
  feedback:all / positive / negative → Sets of query_ids
  cache:{hash}                    → JSON (semantic cache entry, TTL 3600s)
                                    Contains: query, answer, prompt_type, topic, vector

Redis data is EPHEMERAL — metrics and cache rebuild from usage.
User registrations and feedback are lost if Redis is wiped.
There is no automated backup of Redis data.

12. KNOWN ISSUES & FIXES APPLIED
================================================================================

2026-04-16 — OpenAI quota exhausted
  Symptom: All POST /query calls returned HTTP 500 "Internal Server Error".
           Frontend showed this as a CORS error (misleading).
  Root cause: openai.RateLimitError code=insufficient_quota on embeddings call
              (elastic_retriever.py:31 → embed_query) and query classifier.
  Fix: Updated OPENAI_API_KEY in Key Vault + .env. Forced new container revision.
  Prevention: Monitor usage at platform.openai.com/usage. Set billing alerts.

2026-04-16 — CORS false alarm
  Symptom: Browser reported CORS error on /query.
  Actual cause: HTTP 500 from backend (see above). CORS was correctly configured.
  Note: When backend crashes before sending response headers, browsers
        report it as a CORS error. Always check backend logs first.
  How to verify CORS is working:
    curl -v -X OPTIONS <backend>/query \
      -H "Origin: https://ai.truos.io" \
      -H "Access-Control-Request-Method: POST"
    Look for: access-control-allow-origin: https://ai.truos.io

2026-04-16 — Key Vault RBAC not set for info@truos.io
  Symptom: az keyvault secret show/set/list all returned ForbiddenByRbac.
  Root cause: info@truos.io had Owner on subscription and Secrets Officer on
              aigov-kv (different vault) but NOT on gov-demo-kv-truos.
  Fix: Granted Key Vault Secrets Officer role via ARM REST API:
    az rest --method PUT \
      --url "https://management.azure.com/.../roleAssignments/<uuid>?api-version=2022-04-01" \
      --body '{"properties":{"roleDefinitionId":"...b86a8fe4...","principalId":"7df538c9...","principalType":"User"}}'
  Note: az role assignment create kept failing with MissingSubscription error
        (Azure CLI bug); ARM REST API call succeeded.

2026-04-16 — GitHub Actions Node.js 20 deprecation warning
  Actions affected: actions/checkout@v4, dorny/paths-filter@v3
  Fix: Added FORCE_JAVASCRIPT_ACTIONS_TO_NODE24: true to workflow env block.
  Deadline: June 2026 (would have broken without fix).

13. SECURITY NOTES
================================================================================

.env file:
  - Gitignored. NEVER commit .env to git.
  - Contains live secrets for local dev only.
  - Production secrets ONLY live in Key Vault.

Secret rotation:
  - Update Key Vault secret value
  - Force new container revision (see Section 5 rotation command)
  - Update GitHub Actions secret if also used in CI

CORS policy (api.py:26-33):
  - Origins read from CORS_ORIGINS env var (comma-separated)
  - .strip() applied to each origin (whitespace-safe)
  - allow_credentials=True requires explicit origins (no wildcard)
  - Current allowed origins: localhost:3000, SWA default, ai.truos.io

Rate limiting (security.py):
  - In-memory sliding window: 10 requests/user/60s
  - NOT Redis-backed — resets on container restart/scale-out
  - Each replica has independent rate limit state
